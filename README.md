# Tasty Travels 3D — 世界屋台マージ

「[Tasty Travels: Merge Game](https://www.centurygames.com/games/tasty-travels/)」風のマージ・パズルを、
**本物の WebGL 3D 空間**（透視投影・遮蔽・視差・実ジオメトリ）で実装したものです。
CSS による擬似 3D は一切使っていません。板ポリの貼り絵でもありません。

丘の上のテラスに自分の屋台を構え、木箱から食材を出し、同じ食材を重ねてマージし、
カウンターの向こうに立つお客さんの注文へ届けます。コインが貯まれば次の街へ。

```
リスボン（夕暮れ）  →  京都（朝靄）  →  マラケシュ（午後）
```

---

## 遊び方

| 操作 | 内容 |
| --- | --- |
| 木箱・袋をタップ | エネルギーを消費して食材を1つ出す（作業台の四隅が仕入れ口） |
| 食材をドラッグして重ねる | 同じ食材どうしがマージして 1 段上の品になる（全4系統 × 5段） |
| 注文の品をお客さんへドラッグ | コイン・経験値・エネルギーを獲得 |
| 背景をドラッグ | 視点を回す（近景・中景・遠景の視差が出ます） |
| ホイール / ピンチ | ズーム |
| 「✈ 次の街」 | コインを払って別の街へ旅立つ（世界がまるごと組み直されます） |

進行状況は `localStorage` に自動保存され、エネルギーはオフライン中も回復します。

## 起動

ES モジュールを使うため、`file://` ではなく HTTP で開いてください。

```bash
python3 -m http.server 8000
# → http://localhost:8000/
```

```bash
npx http-server -p 8000 .   # Node 派はこちら
```

必要なのは WebGL2 対応ブラウザだけです。three.js は `vendor/` に同梱しているので、
ビルド手順もネットワーク接続も不要です。

## 奥行きの設計

要件は「一目で奥行きが読める画面」。そのために画面を4層に分け、
各層を**シルエット・材質・光量・空気遠近**で切り分けています。

| 層 | 距離 | 内容 | 分離の手段 |
| --- | --- | --- | --- |
| 近景 | 0.5–1.5 m | カウンター、作業台、皿・秤・包丁、吊るした唐辛子 | 最も高い材質解像度、作業灯による強い接地影 |
| 中景 | 2–8 m | 隣の屋台、街灯、鉢植え、木箱、通行人、鳩、注文客 | 実寸の人体（1.6–1.86 m）が全体の縮尺を決める |
| 遠景 | 15–180 m | 斜面を下る街並み、下町、ランドマーク | 手すりの稜線が境界。以降は霧が支配 |
| 最遠景 | 200 m+ | 水面・平野・山並み | ほぼ霧色。シルエットのみ |

**丘の上のテラスという舞台設定**は、この要件から逆算したものです。
真上に近い盤面視点では、水平線の彼方の街は原理的に画角へ入りません。
そこで屋台を斜面の上に置き、街を**視線より下に**広げました。
屋根の高さは `Environment.maxHouseHeight()` が
「カウンターの目線が手すりをかすめる直線」から逆算して決めており、
どの列の屋根もその直線の数度上に収まります
（近い家が画面を塞がず、奥へ向かって段々に下がって見える理由）。

## 実世界としての妥当性

- **寸法**：メートル単位で統一。カウンター天板 0.92 m・厚み 55 mm、盤面のマス 113 mm、
  トマト直径 66 mm、ソース瓶の高さ 98 mm、街灯 3.9 m、家屋 3.4–9 m。カメラは目線 1.68 m。
- **光**：物理単位。太陽（指向性）＋天空光＋地面反射の3灯に、作業灯のスポット1灯。
  スポットは逆二乗減衰で盤面上の照度が約 1.7 になるよう調整。トーンマッピングは ACES。
- **接地**：影は2枚のシャドウマップ（太陽・作業灯）に加え、
  各食材の足元に減衰マップを敷いたコンタクトシャドウ。
  持ち上げると影は**広がり・薄れ・遅れて追従**します。
- **重量感**：落下は重さ（段位）に応じて反発係数と着地の潰れ量が変わり、
  重い品ほど鈍く着地して埃が多く舞います。
- **材質**：木の年輪と木口・板の継ぎ目の油汚れ、石畳の目地と摩耗した頂点、
  漆喰の雨だれと剥がれ、帆布の織り目と日焼け・カビ——
  すべて手続き的に描いた アルベド／ラフネス／バンプ の3枚組です（画像ファイルなし）。

### 実装上の判断

- **ポストプロセスなし**：`EffectComposer` は使っていません。
  光の滲みは加算ブレンドのハローを光源のそばに置く方式で、
  全画面レンダーターゲット数枚ぶんのコストと、
  一部ドライバでの描画不整合を同時に避けています。
- **`transmission` なし**：屈折材質が1つでもあると three.js は毎フレーム
  シーンをもう一度描き直します。硝子・氷・液体はクリアコート＋アルファで
  同じ見た目を1パスで出しています。
- **`G.freeze()`**：木箱は板20枚、屋台は部品60個。見た目には必要でも、
  そのまま描くと影の分まで含めて描画呼び出しが積み上がります。
  静物は材質ごとに1メッシュへ焼き固めています（1250 → 830 呼び出し）。
- **画質段階**：「画質」ボタンで 高／中／低。
  ピクセル比・シャドウマップ解像度・点光源の有無が切り替わります（端末に応じて自動選択）。

## 動作確認

Playwright（Chromium）で、生成した実際の画面と操作を検証しています。

- 木箱のタップ → 食材の生成・エネルギーと在庫の消費
- ドラッグでの重ね合わせ → 上位品へのマージ
- 注文品を客へドラッグ → 報酬の支払い
- `localStorage` への保存と再読み込み後の復元
- 街の移動 → 世界の再構築

（ヘッドレス環境は SwiftShader によるソフトウェア描画のため実測 fps は参考になりません。
描画呼び出し数・三角形数・実画面のスクリーンショットで確認しています。）
